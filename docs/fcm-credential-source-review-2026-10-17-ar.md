## ما لا يمكن معرفته من Vercel

قيم Secret/Sensitive المحفوظة للكتابة فقط، وليست مجرد قيمة يمكن كشفها بزر Reveal. لذلك لا نستطيع استخراج هوية Google JSON، أو مقارنة مفتاح OneSignal المحلي بالمنشور، أو معرفة اسم/نوع/Key ID مفتاح OneSignal منه. كذلك إعداد المتغير الحالي لا يثبت قيم كل نشر قديم. لا يُنشأ endpoint لكشف الأسرار، ولا يُستبدل متغير للحصول على هويته. [توثيق Vercel](https://vercel.com/docs/environment-variables/sensitive-environment-variables).

### خطة التدوير الآمن المقترحة — غير منفذة

1. **فصل موافقة التبديل عن موافقة الإبطال:** قائمة الموارد المرشحة هي مشروع Vercel notification-server ومتغيراه FIREBASE_SERVICE_ACCOUNT وONESIGNAL_API_KEY، وهويتا FCM الجديدتان المقترحتان aqar-push-vercel وaqar-push-runtime في aqar-9f3f9. مفتاح OneSignal المذكور مرشح فقط للإبطال اللاحق. مفاتيح Google الخمسة وWorker aqar-reels-api ليست قائمة إبطال معتمدة. لا تغيير APNs أو حساب Compute أو هوية firebase-adminsdk نفسها.
2. **بعد موافقة مستقلة فقط:** إنشاء هوية FCM بديلة محدودة، وفصل هوية خادم الإشعارات عن اعتماد الريلز. إذا تقرر إبقاء OneSignal ضمن الخادم يُنشأ مفتاح تطبيق بديل بالتوازي، مع إبقاء القديم وعدم تدويره in-place. إن كان مسار FCM-only لا يحتاج مفتاح OneSignal فعليًا فلا يُنشأ بديل غير لازم؛ يظل أي مسار OneSignal مغلقًا. لا تفعيل إرسال ضمن تبديل الاعتماد.
3. **نشر متوقف بعد الموافقة المحددة:** نشر الثماني Functions والـprivate-only rules patch ومسار /send الآمن كما في خطة النشر السابقة، مع mode=paused وcohort فارغ وpercent=0. بيانات OneSignal/Firebase اللازمة تُحقن كأسرار دون Git/سجلات. لا نشر config شامل أو قواعد Storage أو Worker أو تحديث متجر، ولا تشديد notifications المؤجل ضمن هذه المرحلة.
4. **قبل إلغاء القديم:** توثيق كل مستهلك/نشر نشط يستخدم الاعتماد البديل. يجب حسم مفتاح Google المستخدم في Vercel وWorker ومستهلكي Firebase الآخرين، بما فيهم إعداد FCM لدى OneSignal إن كان يستخدم الحساب نفسه. قراءة metadata الحالية لا تكشف قيم كل نشر Vercel قديم؛ تُحصر أيضًا النشرات القديمة التي ما زالت قابلة لاستدعاء /send قبل الإبطال. لا تعطيل تلقائي لها دون موافقة. إذا ظلت الهوية مجهولة فالإبطال يبقى محجوبًا، حتى لو أمكن تحضير اعتماد بديل معروف.
5. **مراقبة وتراجع:** مراقبة أخطاء المصادقة وHTTP 5xx والدوال وstale attempting/review_required والفوترة، مع استمرار paused. التراجع إلى إصدار آمن متوقف يستخدم الاعتماد البديل، لا إصدار قديم يتجاوز الحصر أو يحمل مفتاحًا ملغى. لا حذف ledger أو الصندوق. بعد تبديل واعتماد كل المستهلكين فقط، يُطلب إذن إبطال المفاتيح المحددة كلٌّ بمعرفه؛ لا إبطال جماعي.

لا يفترض توقف للريلز أو تسجيل الدخول. قد يسبب إلغاء Google المشترك قبل التبديل فشل التحقق الإداري في Worker؛ لذلك لا وعد بانعدام التوقف قبل إغلاق خريطة الاعتماد. يبقى دفع الإشعارات الجديد متوقفًا عمدًا، ولا يتغير وضع OneSignal الحالي. أي تفعيل مجموعة صغيرة موافقة لاحقة منفصلة.

1. اكتملت خطوة تحديد اسم ومعرف OneSignal بإفادة المستخدم أعلاه؛ لا تُعاد. يبقى إثبات ارتباطه بـVercel غير مكتمل. [توثيق الواجهة](https://documentation.onesignal.com/docs/en/keys-and-ids).
2. لا تحتاج إعادة نسخ قائمة Google IAM التي جُمعت بالفعل. إن توفر الملف الأصلي الذي استُخدم لإعداد Vercel، أعطِ مساره فقط لفحص client_email/private_key_id محليًا دون عرض private_key. إن لم يتوفر، صرّح بذلك؛ جدول IAM وحده لا يستطيع حسم المطابقة. للعرض فقط: Google Cloud ← المشروع aqar-9f3f9 ← IAM & Admin ← Service Accounts ← الحساب المذكور ← Keys. لا Add Key ولا Disable ولا Delete. [توثيق Google](https://docs.cloud.google.com/iam/docs/keys-create-delete).
3. يلزم قبل إبطال المفتاح القديم حسم اعتماد Worker aqar-reels-api أيضًا من مصدر إعداده الأصلي أو مسؤول إعداده. صفحة Variables and Secrets قد تثبت اسم السر فقط؛ لا نطلب كشف قيمته أو تعديلها. إذا تعذر التطابق يبقى إبطال المفتاح القديم محجوبًا، مع فصل إنشاء هوية FCM البديلة في موافقة لاحقة.

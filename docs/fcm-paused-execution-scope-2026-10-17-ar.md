## 3. فرق التكوين الصغير اللازم قبل النشر

حزمة التحضير القديمة تربط BRIDGE_ONESIGNAL_API_KEY إلزاميًا عند تشغيل الجسر. لا تُنشر كما هي لهذا النطاق. فرق الإصدار المقترح بالضبط:

- push_onesignal.js في حزمة Functions والخادم: إذا BRIDGE_ONESIGNAL_ENABLED=false تُعيد providerSecretOptions إعدادًا بلا secrets، ويرفض providerConfig أي طلب OneSignal قبل الشبكة. عند غياب العلم يبقى السلوك السابق، حفاظًا على بقية البيئات.
- ملف بيئة Functions يضبط BRIDGE_ONESIGNAL_ENABLED=false. ملف دخول Vercel لا يطلب وجود مفتاح OneSignal ولا يربطه بـBRIDGE_ONESIGNAL_API_KEY عند هذا العلم؛ يبقى متغير ONESIGNAL_API_KEY نفسه دون تغيير.
- لا تغيير كود Android/iOS أو السياسة المشتركة لمنع التكرار أو التوجيه. لا حاجة لبناء متجر جديد.

هذا **وصف فرق محدد للمراجعة وليس ادعاء اكتمال اختبار كود جديد**. عند إعداد فرق الإصدار قبل تنفيذ الإنتاج يلزم تحقق محلي ضيق فقط: العلم false يمنع ربط السر ويمنع HTTP إلى OneSignal، مع بقاء paused/cohort فارغًا. نتائج الأجهزة والتوافق وCI السابقة لا تُعاد؛ إذا احتاج الإصدار CI تقتصر الإعادة على التغيير المؤثر وفق سياسة المستودع. لا نشر قبل نجاح هذا التحقق. لا تعديل source code أثناء هذه الجولة التخطيطية.

## 5. ترتيب التنفيذ والتراجع

بعد موافقة صريحة على هذه القائمة: تجهيز فرق التكوين المحدد والتحقق الضيق، ثم حفظ metadata الإصدار الحالي ونسخة القواعد دون نسخ الأسرار، وإنشاء IAM الجديد، ونشر الحصر والقيمة paused قبل أي dispatcher، ثم Functions والخادم، ثم مطابقة metadata وحالة paused ومراقبة بدء التشغيل. لا إرسال حقيقي للتحقق في هذه المرحلة.

في حال مشكلة: يبقى paused والمجموعة فارغة وإذن FCM غير ممنوح. توقف الموارد الجديدة المتأثرة أو تعاد إلى إصدار صيانة آمن متوقف، وتستعاد القواعد السابقة فقط إن لم يطرأ نشر متزامن. لا rollback إلى /send القديم غير المقيد، ولا إبطال اعتماد الريلز أو OneSignal، ولا حذف الصندوق أو ledger. النسخ القديمة لا تستعيد Push بمجرد هذا النشر؛ استعادة الإرسال تأتي فقط بموافقة canary منفصلة. خلل بدء خادم الإشعارات قد يعطل /send مؤقتًا؛ لا توقف متعمد لتصفح التطبيق أو الريلز أو الرفع.

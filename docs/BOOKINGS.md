# الحجوزات — التنفيذ الأول

الفرع `feature/bookings` مبني على أحدث `origin/main` وقت التنفيذ (كانت النسخة المحلية متأخرة 13 commit). لا توجد تعديلات سابقة في النسخة المحلية. لم يتم نشر أو دمج التغييرات.

## الاستخدام

- زر الحجوزات مستقل بالشريط السفلي، دون تغيير أرقام الدردشة والريلز والإعلان الحالية.
- لوحة الإدارة: إضافة وتعديل أماكن الحجز وتحديد حساب المالك بالاسم والهاتف، والفئة (شاليه/مزرعة/قاعة/أخرى)، والموقع والسعر والعربون والشروط والتفعيل.
- الزبون يختار البداية والنهاية ويوافق على السعر والشروط. كل طلب يحفظ نسخة من بيانات الأطراف والأسماء والهواتف والأسعار والشروط.
- لوحة المالك تعرض طلباته وتسمح بالموافقة أو الرفض والإلغاء قبل الدفع. الموافقة تحجز الموعد مؤقتاً لمدة تحددها الإدارة، افتراضياً 120 دقيقة، وبحد أقصى بداية الحجز.
- كي وزين كاش: تحويل يدوي، رفع صورة إيصال ورقم التحويل، ثم مراجعة الإدارة. لا توجد بوابة دفع آلية. المبلغ المعتمد يصبح العربون فقط، والمتبقي = الإجمالي - العربون.
- مراجعة الإيصال تحجز الموعد حتى قرار الإدارة؛ رفض الإيصال يحرر الموعد وينهي الطلب. العميل يمكنه تقديم طلب جديد.
- إشعارات داخلية وFCM للزبون والمالك وكل حساب إدارة غير محظور، مع فتح تفاصيل الحجز. إعادة تشغيل الحدث لا تنشئ إشعاراً مكرراً.
- بلاغات خاصة بالأطراف، ولوحة إدارة لعرضها وإغلاقها.

## الحماية والاختبارات

الأسعار والأطراف والحالات تُكتب بالخادم فقط. لا يسمح للعميل بتغييرها مباشرة، حتى لو كان أدمن. معاملات Firestore تسلسل تغييرات مخزون كل مكان عبر مستند المكان، وتمنع قبول طلبين متداخلين بالتزامن. نهايات المواعيد غير شاملة، لذلك يسمح بحجز يبدأ عند نهاية حجز سابق. الحجز المؤقت المنتهي لا يمنع الطلبات الجديدة حتى قبل تشغيل المهمة الدورية كل خمس دقائق. صور الإيصالات في Storage خاصة بالأطراف والإدارة، غير قابلة للاستبدال.

تشغيل الاختبارات:

```text
node --test functions/booking_policy.test.js
firebase emulators:exec --only firestore,storage --project demo-aqar --config firebase.bookings-test.json "node test/run_booking_tests.cjs"
flutter test --no-pub test/booking_navigation_test.dart test/navigation_return_test.dart
flutter analyze --no-pub lib/bookings lib/services/notification_navigation_service.dart lib/screens/main_shell.dart lib/widgets/navigation/custom_bottom_bar.dart lib/screens/admin/admin_dashboard.dart
```

## قرارات قبل النشر

نتائج التحقق المحلي: نجحت 3 اختبارات سياسة الحجوزات، واختبار تكامل دورة الحجز (يشمل التزامن وانتهاء المهلة وحظر الحساب والبلاغات والإشعارات)، و3 اختبارات قواعد Firestore/Storage (بما فيها منع استبدال الإيصال)، و3 اختبارات Flutter للتنقل. فحص Flutter للملفات المتأثرة لا يحتوي أخطاء أو تحذيرات؛ بقيت ملاحظة تنسيق سابقة في `main_shell.dart`. أضيفت الاختبارات إلى workflow للمراجعات؛ لم يُنفّذ بناء iOS أو Android كامل محلياً.

1. تأكيد حسابات التحويل: لوحة الإعدادات تبدأ بدون حسابات، ولا تسمح برفع دفع لطريقة غير مهيأة. لا يوجد رقم زين كاش موثوق في آلية الاشتراكات الحالية، فلا يتم اختلاقه. آلية الاشتراكات الحالية تتطلب إيصال كي؛ الحجوزات تتطلب الإيصال للطريقتين حسب الطلب.
2. التسعير الحالي مبلغ ثابت لكل فترة حجز يحددها المالك مع الإدارة، ولا يحسب سعر اليوم أو الساعة أو الشفت تلقائياً. يلزم حسم تقسيم الشفتات والتسعير الموسمي قبل توسيعها.
3. حجوزات مؤكدة أو إيصالات قيد المراجعة لا يمكن إلغاؤها من زر الإلغاء؛ يلزم الاتفاق على سياسة الاسترداد والتسويات اليدوية قبل إضافة إجراء مالي لإلغائها. نص الشروط يحدد السياسة الآن.
4. الصلاحيات الحالية تستخدم `isAdmin` للإدارة والمراجعة المالية؛ لا يوجد فصل جديد بين المحاسب والمدير. يلزم حسم أسماء ومجالات صلاحيات مالية إضافية قبل إضافتها.
5. أماكن الحجز مستقلة عن إعلانات العقارات؛ لا تُحوّل الإعلانات الحالية تلقائياً. الإدارة تسجل الأماكن وتتحقق من الملاك. يلزم تأكيد ربط المكان بإعلان موجود إن كان مطلوباً.
6. يلزم تجربة تشغيلية على جهاز فعلي لإشعارات FCM ورفع صور حقيقية وقبول الشروط، مع بيانات تجريبية، قبل تفعيل الأماكن للجمهور. قوائم الوحدة الأولى غير مقسمة إلى صفحات؛ يجب إضافة pagination قبل نمو البيانات الكبير.

ترتيب النشر بعد الاعتماد: الفهارس والقواعد ثم Functions ثم التطبيق. تهيئة حسابات التحويل والمدة والأماكن من لوحة الإدارة. يتطلب Cloud Scheduler وStorage إعداد المشروع المناسب. الاختبارات تستخدم مشروع demo محلياً ولا تتصل ببيانات الإنتاج.

## قرارات تحفظ المال والتوافق

- العمولة صفر ما لم يحددها مدير. أساسها **العربون المقبوض**، وليس كامل سعر الحجز. يحفظ الحجز النسبة عند طلبه؛ تعديل المكان لا يغير عقدًا سابقًا.
- تقرير الدفتر يعرض العربون المعتمد والاستردادات وتسويات الملاك والعمولة. الباقي غير المحصّل لا يُعد إيرادًا نقديًا. البيانات التاريخية قبل إضافة الدفتر لا تُختلق لها قيود.
- اعتماد إيصال أو إدخال مرجع تسوية إجراء مراجعة بشرية؛ لا يُسمّى دفعًا أو استردادًا آليًا. يحتاج مراجعًا مستقلًا عن المالك والزبون والموظف المفوض للمكان.
- يرفض نقل الملكية مع معاملات قائمة؛ الحجوزات السابقة تحتفظ بمالكها وبيانات عقدها. موافقة المدير لا تعيد كتابة الدفعات السابقة.
- القواعد الجديدة على مجموعات الحجز تمنع كتابة العميل المباشرة؛ العمليات تمر من وظائف مخوّلة. حذف/إغلاق بيانات قديمة أو ترحيلها لم يُنفّذ.

## تشغيل الاختبار محليًا

تتطلب الخطوات أدوات Flutter وFirebase CLI وJava وNode وحزم المشروع. مشروع `demo-aqar` اسم محاكيات، وليس مشروعًا سحابيًا جديدًا. مشغل seed يرفض العمل دون متغيرات محاكيات Auth وFirestore المحلية واسم المشروع المطابق.

1. شغّل المحاكيات فقط:

```powershell
$env:FUNCTIONS_DISCOVERY_TIMEOUT='120'
firebase emulators:start --only auth,functions,firestore,storage,database --project demo-aqar --config firebase.bookings-local.json
```

2. في نافذة ثانية من جذر المستودع، أضف fixtures:

```powershell
$env:GCLOUD_PROJECT='demo-aqar'
$env:FIRESTORE_EMULATOR_HOST='127.0.0.1:8185'
$env:FIREBASE_AUTH_EMULATOR_HOST='127.0.0.1:9099'
node functions/seed_booking_emulators.js
```

3. اربط الهاتف أو محاكي Android بواسطة USB/ADB ومرّر المنافذ:

```powershell
adb install -r aqar-bookings-test.apk
adb reverse tcp:9099 tcp:9099
adb reverse tcp:5001 tcp:5001
adb reverse tcp:8185 tcp:8185
adb reverse tcp:9198 tcp:9198
adb install -r aqar-bookings-test.apk
```

4. افتح نسخة الاختبار واختر الزبون أو المالك أو الإدارة أو المالية. الحسابات `customer/owner/admin/reviewer@test.invalid` وكلمة المرور `AqarTest123!` تخص المحاكيات فقط. أرقام الدفع كلها وهمية واضحة؛ لا تحول أموالًا. لكل حساب جلسة منفصلة عند العودة لشاشة الاختيار.

بناء الاختبار: `flutter build apk --debug --flavor bookingsTest --target lib/bookings_test_main.dart`. يمكن تحديد `BOOKINGS_EMULATOR_HOST` عند البناء لمضيف شبكة اختبار؛ المضيف الافتراضي `127.0.0.1` يتطلب تمرير المنافذ أعلاه. محاولة تشغيل المدخل التجريبي دون flavor الاختبار تُرفض، واستخدام flavor الاختبار مع المدخل المعتاد يُحوّل إلى بيئة المحاكيات قبل تهيئة Firebase الإنتاج.

## ما يلزم قبل أي إطلاق

استكمال النواقص الداخلية المحددة في الجدول، وقبول بصري وتدفقات على أجهزة حقيقية، وبيئة staging سحابية مخوّلة مستقلة مع إعداد الإشعارات والتخزين والفهارس والمجدول، وخطة انتقال وتراجع واحتفاظ وتطابق مالي. بوابة الدفع الرسمية تبقى موردًا خارجيًا منفصلًا؛ لم أطلبها أو أفعلها. **لا نشر إنتاج أو متجر أو دمج إلى main دون موافقة صريحة مستقلة.**

نتائج الجولة النهائية وروابط commits وبصمة APK مرفقة في تقرير التسليم في `outputs`، لأن وقت الاختبار والبناء وSHA التسليم يُثبت بعد إتمامهما.

# تحقق شرطَي الصندوق وحصر المجموعة — 17 أكتوبر 2026

**PASS / PASS ضمن التحقق المعزول المحدود.** لا تغيير إنتاجي، لا إرسال فعلي، ولا اختبار هاتف/Preview/حمل أو إعادة بناء. مصدر التغيير خادمي فقط؛ مرشحا المتاجر السابقان لا يحتاجان إعادة بناء لهذا التغيير.

| الشرط | النتيجة والدليل |
|---|---|
| حفظ الإشعار المرئي للمستلم | PASS: dispatcher المشترك يحفظ قبل استدعاء المزود، ويغطي صندوق الإدارة وHTTP الموثق ومصادر التعليق/الرد/المحادثة. تُحفظ هوية الوجهة والعنوان/النص ووقت الإنشاء، ويستطيع المستلم القراءة ويُرفض الحساب الآخر. |
| حصر الحساب/الجهاز والمزود | PASS: cohort فارغ/غائب يرفض الجميع، ويتطلب UID مع الجهاز نفسه أو legacy target نفسه ومزود معتمد؛ لا اعتماد على percent لتفويض الجمهور، ولا fallback OneSignal خارج القائمة. يعاد الفحص داخل معاملة الحجز. |

## التغيير المنفذ في الفرع المعزول

- عنصر واحد مرئي لكل حدث موثق: استخدام صندوق العميل الموجود أو إنشاء عنصر server داخلي ثابت إن غاب. طي نسخة عميل لاحقة مثبتة لنفس الحدث والمستلم، ودمج حالة قراءتها، دون إعادة إرسال أو مسح صندوق حساب آخر. لا إحياء عنصر حذفه المستلم. حدث المصدر وعملية العميل المتزامنان انتهيا بعنصر واحد وإيصال واحد.
- حفظ الصندوق مستقل عن pause وتفضيل الدفع وcohort، مع منع إرسال إذا فشل الحفظ أو اختفى العنصر أو اختلف المستلم. الطلب HTTP غير المثبت يظل مرفوضًا/معلقًا بلا إرسال؛ لا نحفظ payload عام غير موثوق.
- cohort جديد fail-closed: userIds، installations على شكل [{uid,id}]، legacyTargets على شكل [{uid,key}]، providers. القائمة القديمة legacyRecoveryAllowlist وموافقة الرمز تظلان مطلوبتين للاستعادة، لكنهما لا تتجاوزان cohort.
- دالة sendNotificationToUser القديمة في مصدر index تتوقف عند PUSH_BRIDGE_ENABLED=true؛ deliverFcmNotification كان يتوقف سابقًا عند تشغيل الجسر. لا نشر لهاتين الدالتين القديمتين إلى الإنتاج ضمن القائمة المقترحة.

## التحقق فقط مما تأثر

**النسخة النهائية: 8 حالات سياسة ناجحة + 7 حالات تكامل ناجحة، صفر فشل.** محاكي Firestore demo-aqar على 127.0.0.1:8185؛ Auth وFCM وOneSignal مبدلة باستدعاءات اختبار، مع تأكيد وجود عنصر الصندوق للمستلم قبل كل provider callback. ليست إيصالات إرسال حقيقية، ولا ادعاء إعادة اختبار تطبيق متجر.

الحالات تغطي الأنواع المارة بصندوق الإدارة، وHTTP، والمصادر الثلاثة، وقراءة المستلم مقابل حساب آخر، وpause/opt-out، وفشل الحفظ/الحذف/المستلم الخطأ، وcohort مفقود/فارغ/جهاز أو حساب أو مزود أو هدف legacy غير معتمد، وزوج حساب/جهاز غير مطابق، وإرسال FCM وOneSignal المسموح فقط، وسحب الموافقة بعد التخطيط، وحارس المرسل القديم، وسباق المصدر/العميل. ثلاث حالات انحدار موجودة تخص معاملات الجسر المتأثرة نجحت في الجولة الأولى أيضًا؛ لم تُعد بقية اختبارات المشروع.

أعيدت الحالات المحدودة بعد تشديد ربط الجهاز بحسابه وإضافة تحقق السباق؛ هذا تغيير مؤثر محدد، لا تكرار بلا سبب. لم تُعد Android/iPhone أو Preview الحقيقي أو الحمل أو full CI أو native builds. أضيف ملف الاختبار الجديد إلى مسار CI المستقبلي؛ التحقق الحالي محلي محدود وليس ادعاء نجاح CI كامل للمصدر الجديد. التحذير MetadataLookupWarning في المحاكي لا يمثل طلب دفع أو خطأ اختبار؛ انتهى runner والمحاكي بنجاح.

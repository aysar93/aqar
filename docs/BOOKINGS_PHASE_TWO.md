# الحجوزات — المرحلة الثانية

بدأ العمل من `a561590` على `feature/bookings`. تم فحص تقرير المرحلة الأولى في `outputs/BOOKINGS.md` من المحادثة السابقة ومطابقته مع `docs/BOOKINGS.md` والكود. لا دمج في main ولا نشر Firebase أو التطبيق.

## التغييرات

- مصدر مشترك لحسابات تحويل الاشتراكات والحجوزات: `functions/subscription_payment_accounts.json`. حساب كي مأخوذ حرفياً من شاشة اشتراكات المكاتب الحالية. شاشة الاشتراكات تقرأ نفس الملف كـ asset، وخادم الحجوزات يقرأ الملف مباشرة ويعيد بياناته للتطبيق. لم تُقرأ بيانات إنتاج ولم يتم اختلاق حساب. خيار زين كاش الحالي في الاشتراكات لا يحتوي رقماً؛ يبقى معطلاً في الحجوزات حتى إضافة بيانات موثّقة للمصدر المشترك. حسابات `settings/bookings` القديمة لا تتحكم في التحويل بعد هذا التغيير؛ يحتفظ كل دفع بالحساب الذي استُخدم.
- نوع تسعير لكل مكان: ثابت، شفتات، أو ساعة. لكل شفت اسم ومعرف ووقت دخول وخروج وسعر مستقل. الأوقات بتوقيت بغداد UTC+03:00؛ خروج قبل الدخول أو مساوٍ له يعني اليوم التالي. الساعة اختيارية وتقبل ساعات كاملة فقط. الخادم يحسب السعر ويتحقق من الوقت والسعر والسياسة التي وافق عليها العميل؛ لا يثق في سعر العميل. العربون مبلغ ثابت لا يتجاوز سعر أي شفت أو ساعة. نسخة التسعير والأطراف والموقع والشروط والسياسة محفوظة في الحجز.
- الإدارة تحدد مهلة الاسترداد الكامل بالساعات قبل الدخول، ونسبة استرداد العربون بعدها (0–100). لا قيم افتراضية تخمينية. إلغاء المالك أو الإدارة قبل الدخول يستحق كامل العربون. لا إلغاء بعد الدخول. الحجز الملغى لا يطلب باقي قيمة الحجز، مع حفظ المتبقي التعاقدي للتدقيق.
- الإلغاء قبل الدفع يحرر الموعد. الإلغاء بعد اعتماد العربون يحسب مبلغ الاسترداد ويفتح تسوية يدوية. الإلغاء أثناء مراجعة الإيصال ينتقل إلى `cancel_requested` ويظل مانعاً للتعارض حتى قبول الإيصال أو رفضه بواسطة مراجع مالي. وقت طلب الإلغاء هو وقت احتساب السياسة. رفض الإيصال لا ينشئ استرداداً. تسجيل التسوية يتطلب مرجع تحويل، ويسجل المراجع والوقت والمبلغ، ويمنع التكرار.
- صلاحية مستقلة `canReviewBookingPayments`؛ `isAdmin` وحدها لا تعتمد الدفعات ولا تسوي الاسترداد. يمنحها المدير من إعدادات الحجوزات عبر دالة خادم موثّقة. لا يستطيع المستخدم إضافتها عند إنشاء حسابه أو تعديله، ولا المدير عبر كتابة مباشرة. حتى المراجع المالي لا يراجع دفعاً أو استرداداً يكون هو العميل أو المالك فيه. لوحة المراجعة المالية متاحة من زر الحجوزات للمراجع دون إعطائه صلاحيات الإدارة العامة أو البلاغات.
- الحفاظ على زر الحجوزات وزر الإبلاغ وبيانات الحجز الكاملة وإشعارات المالك والإدارة؛ إضافة المراجعين الماليين وإشعار التسوية مع منع التكرار. مفتاح منع تكرار فتح إشعارات التطبيق يتضمن معرف الحجز.
- تحويل صورة الإيصال إلى JPEG فعلياً قبل رفعها، مع استمرار خصوصية الصور وعدم استبدالها وحد الحجم 10 MB ومهلة الدفع.
- بناء Android التجريبي لا يحتاج مفتاح توقيع الإنتاج؛ بناء Release يرفض غياب ملف التوقيع. أضيف بناء Android وفحوص المرحلة الثانية وتشغيل الفرع إلى workflow الحالي، مع إبقاء بناء iOS دون توقيع على macOS. لا خطوات نشر في workflow.

## التحقق المحلي

نجحت 8 اختبارات سياسة وحسابات وحمولة FCM، واختبارا تكامل للخادم في محاكيات demo، و4 اختبارات صلاحيات Firestore/Storage، و7 اختبارات Flutter للشفتات والحساب المشترك والشاشات والتنقل. نجحت إعادة التشغيل بعد تعديلات السياسة. فحص Flutter للملفات المعدلة بلا أخطاء أو تحذيرات؛ توجد 6 ملاحظات deprecated_member_use سابقة في RadioListTile بشاشة اشتراكات المكاتب. نجحت أيضاً فحوص الخادم والقواعد على GitHub باستخدام Node 24.

الأوامر القابلة للإعادة:

```text
node --test functions/booking_policy.test.js
firebase emulators:exec --only firestore,storage --project demo-aqar --config firebase.bookings-test.json "node test/run_booking_tests.cjs"
flutter test --no-pub test/booking_phase_two_test.dart test/booking_navigation_test.dart test/navigation_return_test.dart
flutter analyze --no-pub --no-fatal-infos lib/bookings lib/subscription/payment_accounts.dart lib/subscription/screens/payment_screen.dart lib/services/notification_navigation_service.dart
flutter build apk --debug
```

## القيود المطلوبة قبل الاعتماد

1. زين كاش يحتاج رقماً موثّقاً؛ وجود اسم الطريقة في شاشة الاشتراكات ليس دليلاً على حساب تحويل.
2. يجب إعداد سياسة الإلغاء للأماكن القديمة قبل قبول طلبات جديدة. الحجوزات القديمة المدفوعة التي لا تحمل سياسة لا تُلغى مالياً بهذه الدوال؛ تحتاج سياسة تسوية معتمدة دون تطبيق سياسة جديدة بأثر رجعي.
3. الاسترداد تحويل يدوي، وتسجيل مرجعه لا ينفذ تحويلاً مصرفياً. المدفوعات المعتمدة تغطي العربون فقط؛ باقي القيمة خارج مسار التحويل الحالي.
4. إشعارات المحاكيات تختبر المستلمين وعدم التكرار ومستندات الإشعار. لا إثبات لتسليم FCM/APNs على جهاز فعلي أو تجربة اختيار/ضغط صورة حقيقية على Android/iPhone. يلزم ذلك قبل تفعيل الجمهور.
5. بناء Android المحلي ينتظر تنزيل Gradle. بناء iOS غير متاح محلياً على Windows؛ النتائج الخارجية ستُسجل من GitHub Actions إن توفر التشغيل. لا يُعد إعداد workflow نجاح بناء.
6. القوائم الحالية لا تزال دون pagination. صلاحية المراجع المالي تتيح قراءة حجوزات وإيصالات النظام لمراجعتها؛ لا تتيح إدارة الأماكن أو البلاغات أو الاشتراكات.
7. البيئة المحلية Node 26 بينما Functions تطلب Node 24؛ workflow يستخدم Node 24. ظهرت ملاحظات تبعيات قديمة أثناء التثبيت ولم تُجرَ ترقيات واسعة خارج هذه المهمة.

أي نشر أو دمج أو تغيير حسابات/سياسات الإنتاج يحتاج موافقة المستخدم بعد عرض نتائج الفحوص والقيود.
